🩺 Pulso dos Bugs — o resumo do que está acontecendo
Tipo de item = Bug · Classificação de Bug = Cliente/externo e Sem classificação
🧭 Para decidir: as 4 perguntas
🚩 Segmentos que merecem atenção
ℹ️ Como é calculado: cada segmento ganha pontos por % de pendentes fora do SLA (a partir de 15%: 1 ponto; de 35%: 2), % com prazo vencido (de 10%: 1; de 25%: 2), fila crescendo nos últimos 30 dias (1) e 5 ou mais bugs parados há mais de 1 ano (1). Com 4 pontos ou mais é Prioridade; com 2 ou 3, Atenção. Segmentos com menos de 10 pendentes aparecem como "Poucos bugs" e não são avaliados. A lista ignora o filtro de Segmento, para comparar um com o outro.👆 Clique numa linha para ver os bugs pendentes daquele segmento fora do SLA.
📚 Informações completas
1️⃣ O que está pendente?
Bugs que ainda não foram resolvidos hoje. Quanto mais à direita/vermelho, mais antigo o problema.
📅 Pendentes por ano em que o bug foi criado (clique numa cor ou linha)
ℹ️ Como é calculado: conta os bugs pendentes hoje, agrupados pelo ano em que foram criados.👆 Clique numa cor ou numa linha da lista para ver quais são os bugs.
⏳ Há quanto tempo estão parados (envelhecimento)
ℹ️ Como é calculado: conta os bugs pendentes hoje pelo tempo desde a abertura (hoje − data de criação), dividido em faixas de dias.👆 Clique numa cor ou numa linha da lista para ver quais são os bugs.
🧭 Em que etapa estão os pendentes (clique numa etapa)
⏰ Prazo dos pendentes (clique numa cor ou linha)
ℹ️ Como é calculado: cada etapa junta os status do Jira dos bugs pendentes (os status aparecem abaixo do nome da etapa). O prazo vem do campo de prazo da tarefa.👆 Clique numa etapa, numa cor ou numa linha para ver quais são os bugs.
2️⃣ Quanto entrou, quanto saiu, quanto reprovou?
Entrou = bug novo aberto no mês · Saiu = bug que saiu da fila: resolvido (finalizado) ou reprovado (a análise concluiu que não era bug / não procede). O número destacado em cima da coluna é o total que saiu.
📈 Movimento mês a mês (clique numa cor · passe o mouse para ver os detalhes)
ℹ️ Como é calculado: Entrou = bugs criados no mês · Saiu = bugs resolvidos (status Finalizada) somados aos reprovados (status "Análise Reprovada") no mês, pela data de resolução — as duas cores mostram a divisão e o número destacado é o total · Saldo do período = Entrou − Saiu (positivo = a fila cresceu; negativo = diminuiu).👆 Clique numa cor da coluna para ver os bugs · passe o mouse na coluna Saiu para ver quantos foram abertos neste ano e em anos anteriores.
3️⃣ A vida do bug
Quanto tempo um bug fica aberto até ser resolvido, e quanto tempo os que ainda estão abertos já esperam — separado por criticidade (a gravidade do bug).
⏱️ Tempo médio por criticidade (clique numa barra)
ℹ️ Como é calculado: Já resolvidos = média de dias entre a criação e a resolução dos bugs finalizados no ano · Ainda abertos = média de dias entre a criação e hoje dos bugs pendentes.👆 Clique numa barra para ver quais são os bugs.
📋 Resumo por criticidade
ℹ️ Como é calculado: mesma conta do gráfico ao lado. "Mais demorado" e "mais antigo" mostram o maior tempo daquele grupo; a linha Σ Total soma todas as criticidades.
⏱️ Em quanto tempo os bugs são resolvidos (clique numa cor ou linha)
📈 Média e mediana de dias para resolver, por mês
ℹ️ Como é calculado: dias entre a abertura e a resolução dos bugs finalizados no ano. A mediana é o valor do meio (não se distorce com poucos casos muito demorados); a média soma tudo e divide pela quantidade, por isso sobe quando há bugs muito demorados. Ambas são agrupadas pelo mês em que o bug foi resolvido.👆 Clique num ponto da linha para ver os bugs daquele mês.

As tarefas mais apontadas como origem de bugs (campo "Tarefa Origem Inconsistência"). Quanto maior a barra, mais bugs saíram dessa tarefa; a tabela ao lado mostra do que se trata cada uma.

De onde o problema nasce (código ou análise), se é bug antigo ou novo e quais assuntos mais aparecem nos títulos dos bugs abertos no ano.
🧬 Motivo do bug (origem)
🕰️ Erro legado ou erro novo

ℹ️ Como é calculado: considera os bugs abertos no ano, sem os reprovados. Motivo = campo "Origem do Bug"; legado × novo = campo "Bug Gerado"; temas = em quantos títulos cada palavra aparece (palavras genéricas como ajuste, correção e erro são ignoradas — é uma leitura aproximada, vinda de texto livre).👆 Clique numa fatia, numa linha da legenda ou numa barra para ver quais são os bugs.
